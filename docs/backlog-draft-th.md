# PairEval: Product Backlog (ฉบับภาษาไทย)

นี่คือแบบร่าง User Stories ทั้ง 8 ข้อสำหรับระบบ PairEval (ระบบประเมินผลแบบจับคู่ Pairwise) โดยเขียนให้อ่านง่ายสำหรับทุกคนในทีม

---

## User Story 1: ล็อกอินด้วยบัญชีมหาวิทยาลัย (Google OAuth)
**ในฐานะ** นักศึกษาหรืออาจารย์ 
**ฉันต้องการ** เข้าสู่ระบบด้วยบัญชี Google ของมหาวิทยาลัย 
**เพื่อที่จะ** ยืนยันตัวตนได้อย่างปลอดภัยโดยไม่ต้องสมัครสมาชิกหรือจำรหัสผ่านใหม่

### Acceptance Criteria (เกณฑ์การตรวจรับงาน)
- **กำหนดให้** ฉันยังไม่ได้เข้าสู่ระบบ **เมื่อ** ฉันกด "Sign in with Google" และเลือกอีเมลของมหาวิทยาลัย **แล้ว** ระบบจะพาฉันเข้าไปที่หน้า Dashboard
- **กำหนดให้** ฉันพยายามเข้าสู่ระบบ **เมื่อ** ฉันใช้อีเมลส่วนตัว (เช่น @gmail.com ทั่วไป) **แล้ว** ระบบจะปฏิเสธการเข้าใช้งาน พร้อมแสดงข้อความ Error ว่า "กรุณาใช้อีเมลของมหาวิทยาลัยเท่านั้น"

### Definition of Done (เงื่อนไขที่ถือว่างานเสร็จ)
- [ ] ฟีเจอร์ทำงานได้จริงตาม Acceptance Criteria
- [ ] มี Unit test ครอบคลุม Business rule
- [ ] มี E2E test อย่างน้อย 1 ข้อ (เช่น Smoke test เข้าหน้าเว็บได้)
- [ ] Code ผ่านการ Review จากเพื่อนในกลุ่ม
- [ ] Deploy ขึ้น Staging และใช้งานผ่าน URL จริงได้

## User Story 2: สร้างห้องเรียนและนำเข้ารายชื่อกลุ่ม
**ในฐานะ** อาจารย์ 
**ฉันต้องการ** สร้างห้องเรียนและนำเข้ารายชื่อนักศึกษาพร้อมกลุ่มผ่านไฟล์ CSV 
**เพื่อที่จะ** ตั้งค่าเตรียมการประเมินรอบใหม่ได้อย่างรวดเร็ว

### Acceptance Criteria
- **กำหนดให้** ฉันล็อกอินในสิทธิ์อาจารย์ **เมื่อ** ฉันอัปโหลดไฟล์ CSV ที่มีข้อมูลอีเมลและชื่อกลุ่มถูกต้อง **แล้ว** ระบบจะสร้างห้องเรียนและจัดนักศึกษาเข้ากลุ่มให้โดยอัตโนมัติ
- **กำหนดให้** ฉันกำลังอัปโหลด CSV **เมื่อ** ไฟล์มีข้อมูลตกหล่น (อีเมลหาย) หรือรูปแบบผิด **แล้ว** ระบบจะแสดงข้อความแจ้งเตือน Error และยับยั้งการสร้างห้องเรียน

## User Story 3: เปิดเซสชันการประเมิน (Start Evaluation)
**ในฐานะ** อาจารย์ 
**ฉันต้องการ** กดเปิดระบบประเมินสำหรับห้องเรียนนั้นๆ 
**เพื่อที่จะ** ให้นักศึกษาสามารถเริ่มเข้ามาโหวตให้คะแนนเพื่อนในกลุ่มได้

### Acceptance Criteria
- **กำหนดให้** ห้องเรียนมีการจัดกลุ่มเรียบร้อยแล้ว **เมื่อ** อาจารย์กดปุ่ม "เริ่มการประเมิน" **แล้ว** ระบบจะจับคู่ (Pairwise) ให้นักศึกษาในกลุ่มล่วงหน้า และเปลี่ยนสถานะห้องเป็น "Active" (เปิดใช้งาน)
- **กำหนดให้** การประเมินมีสถานะเป็น "Active" **เมื่อ** นักศึกษาล็อกอินเข้ามา **แล้ว** นักศึกษาจะมองเห็นงานที่ต้องทำ (Tasks)

## User Story 4: ดูรายการที่ต้องประเมิน (Dashboard นักศึกษา)
**ในฐานะ** นักศึกษา 
**ฉันต้องการ** เห็นรายการงานประเมินที่ฉันต้องทำบนหน้า Dashboard 
**เพื่อที่จะ** ทราบว่าฉันต้องเข้าไปโหวตให้เพื่อนวิชาไหนบ้างและกำหนดส่งเมื่อไหร่

### Acceptance Criteria
- **กำหนดให้** ฉันเป็นนักศึกษาและมีการประเมินเปิดอยู่ **เมื่อ** ฉันเข้ามาที่หน้า Dashboard **แล้ว** ฉันจะเห็นการ์ดแจ้งเตือน "งานประเมินที่ต้องทำ (Pending)" พร้อมวันหมดเวลา
- **กำหนดให้** ฉันประเมินเพื่อนครบทุกคนแล้ว **เมื่อ** ฉันเข้ามาที่ Dashboard **แล้ว** หน้าจอจะแสดงสถานะว่า "ไม่มีงานค้าง (No pending evaluations)"

## User Story 5: โหวตเลือกเพื่อน (Submit Pairwise Comparison)
**ในฐานะ** นักศึกษา 
**ฉันต้องการ** เลือกโหวตว่าระหว่างเพื่อน A กับเพื่อน B ใครทำงานได้ดีกว่ากัน 
**เพื่อที่จะ** ส่งผลการประเมินของฉันเข้าระบบทีละคู่

### Acceptance Criteria
- **กำหนดให้** ฉันอยู่ในหน้าโหวต **เมื่อ** ฉันเลือกเพื่อน A และกดส่งผล **แล้ว** ระบบจะบันทึกผลการตัดสินของฉัน และโหลดเพื่อนคู่ถัดไปขึ้นมาแสดง
- **กำหนดให้** อินเทอร์เน็ตของฉันกระตุก **เมื่อ** ฉันกดส่งผลไปแล้วเกิด Timeout และระบบส่งข้อมูลซ้ำ (Retry) **แล้ว** ระบบจะต้องไม่บันทึกคะแนนเบิ้ลซ้ำซ้อน (ต้องมีคุณสมบัติ Idempotent)
- **กำหนดให้** ฉันไม่ใช่คนที่ถูกกำหนดให้โหวตคู่นี้ **เมื่อ** ฉันพยายามส่งผลโหวต **แล้ว** ระบบจะเตะออก (ForbiddenError)

## User Story 6: ทำการประเมินเสร็จสิ้น
**ในฐานะ** นักศึกษา 
**ฉันต้องการ** เห็นหน้าจอยืนยันเมื่อโหวตเพื่อนครบทุกคู่แล้ว 
**เพื่อที่จะ** มั่นใจได้ว่าฉันส่งงานประเมินสำเร็จเรียบร้อยแล้ว

### Acceptance Criteria
- **กำหนดให้** ฉันกำลังโหวตเพื่อนคู่สุดท้าย **เมื่อ** ฉันกดส่งผล **แล้ว** ระบบจะพาฉันไปที่หน้า "ขอบคุณ (Thank You)"
- **กำหนดให้** ฉันประเมินเสร็จไปแล้ว **เมื่อ** ฉันพยายามกดลิงก์เดิมเพื่อเข้าหน้าประเมินอีกครั้ง **แล้ว** ระบบจะบล็อกและแสดงข้อความว่า "คุณทำการประเมินนี้เสร็จสิ้นไปแล้ว"

## User Story 7: ติดตามความคืบหน้า (Monitor Progress)
**ในฐานะ** อาจารย์ 
**ฉันต้องการ** เห็นสถานะว่านักศึกษาคนไหนประเมินเสร็จแล้ว หรือยังไม่เสร็จ 
**เพื่อที่จะ** ติดตามและทวงถามนักศึกษาที่ค้างงานได้ถูกคน

### Acceptance Criteria
- **กำหนดให้** ห้องประเมินเปิดอยู่ **เมื่อ** ฉันเข้ามาที่หน้าของอาจารย์ **แล้ว** ฉันจะเห็นแถบ Progress Bar แสดงเปอร์เซ็นต์ของนักศึกษาที่โหวตเสร็จแล้ว (เช่น 25/30 คน)
- **กำหนดให้** ฉันดูรายชื่อนักศึกษา **เมื่อ** ฉันกดฟิลเตอร์เลือก "ยังไม่เสร็จ (Pending)" **แล้ว** หน้าจอจะแสดงเฉพาะรายชื่อคนที่ยังประเมินไม่ครบ

## User Story 8: ดูและส่งออกผลคะแนน (Computed Scores)
**ในฐานะ** อาจารย์ 
**ฉันต้องการ** ดูผลคะแนนรวมและอันดับของนักศึกษาทั้งหมดหลังจากปิดการประเมิน 
**เพื่อที่จะ** นำคะแนนไปใช้ตัดเกรดต่อไปได้

### Acceptance Criteria
- **กำหนดให้** เซสชันการประเมินนั้น "ปิด (Closed)" ไปแล้ว **เมื่อ** ฉันกด "ดูผลลัพธ์" **แล้ว** ฉันจะเห็นตารางรายชื่อนักศึกษาเรียงตามคะแนนที่ถูกคำนวณจากระบบ Pairwise
- **กำหนดให้** ฉันกำลังดูตารางผลลัพธ์ **เมื่อ** ฉันกด "Export" **แล้ว** ระบบจะดาวน์โหลดผลคะแนนออกมาเป็นไฟล์ CSV ลงในเครื่องของฉัน

*(หมายเหตุ: Definition of Done สำหรับ Story 2-8 จะใช้เกณฑ์มาตรฐานเดียวกันกับ Story 1)*
